BELM PORTAL V240 - CHECKLIST SERVICE DATE: DEFAULT + FUTURE-DATE GUARD

Reviewed the "Is this a service day?" -> Service date field used when
a checklist/check-up also records a completed preventive service.

FOUND & FIXED
1. BELM Admin's Check Up form (Customers Manager) never defaulted the
   Service date to today - unlike the Technician's own /tech app form,
   which already did. Admin had to type/pick it manually every time.
   Now defaults to today, same as the Technician form.
2. Neither form stopped someone from picking a FUTURE date as the
   "service completed" date (recording a service that hasn't happened
   yet), which would corrupt the machine's service schedule baseline
   and history. Both date inputs now cap at today (`max` attribute),
   and the backend now also rejects a future service date server-side
   (defense in depth - the HTML `max` attribute alone can be bypassed
   by calling the API directly), with a clear "Service date cannot be
   in the future." error.

VERIFIED (no changes needed)
- Service date format validation (strict Y-m-d, not just "looks like
  a date") was already correct.
- Service type must be one of the fixed 250/500/1000/2000-Hour
  intervals - already correctly enforced.
- Recording a service day correctly updates last_service_hours,
  service_interval_hours, appends to service_history, logs an
  activity_logs "service-completed" entry, and closes any matching
  service-due alert/Draft PI - all consistent and correct.

- Browser/PWA cache bumped to V240.
- No database migration required.
