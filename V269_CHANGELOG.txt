BELM PORTAL V269 - MACHINE TYPE ↔ CHECKLIST TEMPLATE SYNC CHECK

Requested: audit existing machines registered as "Reach Stacker" (and
any other type) so they sync correctly with the Checklist Template
that already exists, plus a Refresh button.

WHY THIS MATTERS
- Check Up looks up a machine's Checklist Template by an exact
  (case-insensitive) match on machine type. A machine typed
  "REACH STAKER" (missing the C) will never match a template correctly
  spelled "Reach Stacker" - Check Up would show "No active Checklist
  Template is assigned to this machine type yet" even though the
  right template genuinely exists, just under a slightly different
  spelling. This kind of drift is invisible from the machine list -
  nothing flags it until someone tries to do a Check Up and it fails.

ADDED
- New panel at the top of Customers Manager: "Machine Type ↔
  Checklist Template Sync", with a "↻ Refresh" button.
- Refresh scans every machine type currently in use and checks it
  against active Checklist Templates. Anything that matches exactly
  shows a single "✓ All N machine(s) match" line - nothing to do.
- Anything that doesn't match exactly is listed with how many machines
  use that spelling, and (using simple text-similarity matching) the
  closest real template name it's probably supposed to be - e.g.
  "REACH STAKER (12 machines)" -> Fix -> "Reach Stacker" (92% match).
- Clicking "Fix" bulk-renames every machine currently using the old
  spelling to the correct one in a single confirmed action, then
  re-checks automatically. If no close template match exists for a
  type, it says so plainly instead of guessing.

BACKEND
- New GET /api/customers?action=machine-type-sync (the audit) and
  POST /api/customers?action=machine-type-sync (the bulk-rename fix),
  both Admin-page-access protected and logged to activity_logs like
  every other bulk change in the portal.

- Browser/PWA cache bumped to V269.
- No database migration required.
