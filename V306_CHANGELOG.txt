BELM PORTAL V306 - FULL REGRESSION HARDENING

1. Service Request / Job Card consistency
   - Unassigning an ASSIGNED request returns Maintenance Process to Workshop Review.
   - Active IN_PROGRESS work cannot be silently unassigned.
   - Cancelled Service Requests close unfinished Job Cards instead of leaving them active.
   - Service Request cannot be marked COMPLETED before the linked Technician Job Card is completed.

2. Technician isolation
   - Technician full Maintenance Process list/detail is backend-restricted.
   - Job Card PDF and signed-copy access require that Job Card to be assigned to the Technician.
   - Technician cannot self-claim an unassigned Job Card by posting a report.
   - Technician spare requests must reference their assigned Job Card and the same maintenance case.
   - Machine action opens My Job Cards directly; badge count uses assigned Job Cards.

3. Billing / debt accuracy
   - Customer outstanding debt uses invoice balance after payments, excluding cancelled/deleted invoices.
   - Service Job Card Proforma/Invoice requires completed Job Card + Workshop closure + signed customer copy.
   - Source Job Card and selected machine must match.
   - Duplicate active Proforma/Invoice for the same Job Card is blocked.

4. Deploy health
   - /api/health returns healthy only when both schema and seeded Super Admin account are ready.

5. Cache
   - Portal tools and service worker bumped to V306.


Additional deep-audit fixes:
- Removed predictable 1234/2026 action-PIN fallbacks and PIN leakage from Settings API.
- Rate-limited PIN verification and blocked generic settings writes to security PIN keys.
- Migration now requires INITIAL_ADMIN_ACTION_PIN only when PINs are missing/legacy.
- Technician API surface now blocks department performance, rosters, machine-wide Job Card history, workflow sync/stage control and Job Card issuing.
- Dispatch no longer offers or reassigns cancelled/completed Job Cards/cases.
- Service Request completion now requires a real completed linked Job Card, including legacy requests.
- Invoice edits cannot relink a Job Card already attached to another active invoice.

- Receipt creation now rejects invoices from another customer and cancelled invoices.
- Proforma source spare requests must match the selected machine.
- Recycle Bin can now restore/permanently remove Receipt and Controller Pinout records that were already sent there.
- Restoring an Invoice/Proforma from Recycle Bin now recomputes the linked Job Card billing status.
- Job Card billing status is now recomputed authoritatively from active Invoice/Proforma state after create/send/cancel/delete/restore, preventing status rollback.
- Recycle Bin blocks restoring an old Invoice/Proforma when a replacement active document already exists for the same Job Card.
- Forgot Password codes are now bound to one exact account ID, preventing legacy duplicate-email accounts from being reset together.
- Forgot Password email generation is rate-limited, and ambiguous legacy duplicate emails fail closed without revealing account existence.
- Recovery-code matching now checks the actual recovery hash across legacy duplicate-email candidates instead of selecting an arbitrary first row.
- Render documentation now reflects the automatic startup migration instead of instructing a manual schema re-import after each deploy.
