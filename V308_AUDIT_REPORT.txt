ISSUE CONFIRMED
- An active Job Card could show Technician: Unassigned while the Breakdown Process already showed DIAGNOSIS / Technician owns the next action.
- Cause: manual Digital Job Card creation always advanced the case to DIAGNOSIS even when technicianId was empty.
- PostgreSQL timestamp strings could also render as a dash/invalid date on Safari/iPhone.

V308 FIXES
- Added TECHNICIAN_ASSIGNMENT stage owned by Workshop / Dispatch.
- New Job Cards advance to DIAGNOSIS only if a Technician was selected.
- Unassigned Job Cards remain AWAITING TECHNICIAN ASSIGNMENT.
- DIAGNOSIS and REPAIR API transitions are blocked until an active Job Card has a Technician.
- Service Request synchronization follows the same assignment rule.
- Deployment migration repairs existing stale cases without resetting the original waiting clock.
- Job Card UI shows an explicit AWAITING TECHNICIAN ASSIGNMENT badge.
- PostgreSQL timestamps are normalized for Safari/iPhone date rendering.
