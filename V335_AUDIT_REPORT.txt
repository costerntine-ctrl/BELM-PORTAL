BELM PORTAL V335 AUDIT REPORT
==============================
Issue: Service Request status tabs showed final records while Daily Report could show zero for the selected date.

Root causes fixed:
- Daily Report previously used TIMESTAMPTZ::date, which follows the PostgreSQL session timezone instead of the portal's Tanzania calendar date.
- Legacy COMPLETED/CANCELLED records can have missing completed_at/cancelled_at values, so they were invisible to the date report.
- Browser default date used UTC toISOString(), which can select the wrong calendar day around local midnight.
- The UI did not explain that status-tab totals are all-date counts while Daily Report is date-scoped.

V335 behavior:
- Final action date is resolved in Africa/Dar_es_Salaam.
- completed_at/cancelled_at falls back to the final STATUS history event, then updated_at/created_at.
- API returns canonical actionAt and handledBy values.
- Daily Report shows selected-date Completed/Cancelled counts and visible status-tab totals together.
- Browser defaults the report date from local calendar components.
- Hidden final records remain available in historical Daily Report; visible totals align with normal status tabs.
