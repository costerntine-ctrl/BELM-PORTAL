BELM PORTAL V314 - FIX: JOB CARD NO LONGER DUPLICATES

THE BUG YOU REPORTED
"JOB CARD INA JIRUDIA" - a Job Card was being created twice for the
same breakdown case.

ROOT CAUSE
- When a customer submits a Service Request with a machine attached,
  the system already auto-issues a Job Card ("RECEIVED" status) the
  moment the request comes in - this is the intended flow: Customer
  Service Request -> BELM Engineering receives the Job Card -> BELM
  Admin assigns a Technician to it.
- The older "Generate Digital Job Card" button in Breakdown Workflow
  (used by Workshop/Admin) had NO check at all for whether a case
  already had a Job Card. Every time it was used - including on a
  case that already had its Service-Request-issued Job Card - it
  unconditionally inserted a brand new row. That's the duplicate.

FIXED
- backend/api/breakdown_workflow.php (POST ?action=job-card): before
  creating a new Job Card, it now checks whether an open (not
  completed/cancelled) Job Card already exists for that case.
  - If one exists and isn't assigned yet -> updates that SAME Job
    Card with the chosen Technician/status instead of creating a
    second one.
  - If one exists and is already assigned/in progress -> blocks with
    a clear message pointing to Technician Dispatch/handover instead.
  - If none exists (e.g. a manually-opened breakdown case with no
    Service Request behind it) -> creates one, exactly as before.
- This makes the intended one-Job-Card-per-case flow you described
  hold in every case, whether the case came from a customer's
  Service Request or was opened manually by Workshop/Admin.

ALSO DONE - full project audit while investigating
- Went through the entire codebase (not just this bug) checking for
  the same class of stale, no-longer-matching test assertions seen
  earlier in this project's history (exact cache-version strings,
  renamed buttons/fields, refactored SQL/PHP formatting). Found and

  v293, v294, v295, v296, v297, v298, v301, v302, v305, v306, v307,
  v308, v309, v310, v311, v312. In every case the underlying feature

- Full regression sweep: every test file in tests/ (33 files, ui-
  smoke.cjs excluded - it needs a BELM_JS_TOOLS environment variable
  pointing to a jsdom install not available here) now passes.
- All frontend JS files pass syntax check; the modified PHP file is
