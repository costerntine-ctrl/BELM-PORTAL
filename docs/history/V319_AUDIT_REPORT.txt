BUGS FOUND AND FIXED
- Sync / Refresh could display success after a sync routine internally failed because lower-level helpers swallowed exceptions.
- The old Service Request state could regress an already-advanced Job Card process.
- IN_PROGRESS Service Request could leave the linked Job Card visually stuck at ASSIGNED.
- Technician Dispatch recovery only inspected a capped subset of Service Requests / received Job Cards.
- Engineering access and Technician Dispatch API access could disagree for an Engineer with Service Requests access.
- Job Card UI could render "undefined" when payload casing/legacy fields differed.
- Confirmed technician spare recommendations did not immediately enter the unified Maintenance Process.
- Customer cancellation lacked a matching Service Request history STATUS event.
- Operator Report closure sync could close a case without adding a process timeline event.
- Engineering landing still contained a stale, unused copy of Technician Dispatch JavaScript after the UI had been moved.

V319 SYNC HEALTH RULES
A full reconciliation now reports attention required when any of these remain after repair:
- active machine-linked Service Request missing a Breakdown Case or Job Card;
- Service Request technician does not match its Job Card technician;
- IN_PROGRESS Service Request has a Job Card that is neither IN_PROGRESS nor COMPLETED;
- completed/cancelled Service Request still has an open Breakdown Case;
- completed Service Request still has a non-completed Job Card.
