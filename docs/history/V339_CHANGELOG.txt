BELM OPERATIONS PLATFORM - V339
Engineering Create Job Card Machine Sync Fix

1. Fixed the Engineering / Technician Dispatch Create Job Card machine selector showing
   "No active machines for this customer" while the customer already had registered machines.

2. Root cause:
   - backend database rows use snake_case fields such as customer_id;
   - BELM api_shape() converts API output to camelCase customerId;
   - the Dispatch UI was still filtering only on machine.customer_id.
   This made the customer filter reject every valid API-shaped machine.

3. Dispatch machine records are now normalized to support both API camelCase and legacy snake_case:
   - customerId / customer_id
   - machineType / machine_type
   - serialNumber / serial_number

4. Selecting a customer now lists all of that customer's registered, non-deleted machines returned by Engineering Dispatch Options.

5. Machine labels and serial numbers also use the normalized API fields.

6. Empty state now says "No registered machines found for this customer" only when the filtered result is genuinely empty.

7. Breakdown Workflow assets, service worker cache, and health release version are bumped to V339 so browsers do not retain the broken selector logic.

8. No database migration is required.
